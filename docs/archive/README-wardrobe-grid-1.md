Godot 4.7.2 的 2.5D 横版格斗 demo，包含“识境演武”短篇试炼和自由对练。当前有云墨丹心、炽翎、白夜执事、影骑士·月轮、雾都迅羽五套战斗流派，共十二套可选外观。对练与识之律者切磋，试炼先挑战识律幻身，最后与本体交战。自由对练使用 Boss 的完整武器调度、半血转阶段和后续入梦必杀；木人模式会停止敌方攻击，包括在白夜必杀运镜中切换木人的情况。敌方使用独立模型，不随玩家换装变化。

白夜执事为独立 `night_squire` 流派：使用原 C3_ND 模型、78 根骨骼、23 段原动作，以及保留原绑定矩阵的双拳套。J 普攻为 A / AA / AAA，K 为 AAB 派生；E 连环腿按原 BAA 的三个接触点命中，获得 3 次后续拳脚强化。Q 播放完整的 1.583333 秒 ND_Ultra 起式，随后 8 秒爆发切换为 B / BB / BBB 和 BBA；爆发随暂停停止计时。使用六个 ND 特效预制体依赖中的原贴图，发射几何与时序适配横版。

红叶知秋使用原客户端 `C3_04_03` 模型与专属原材质，保留 86 根原骨、背包和肩带骨、原蒙皮及拳套绑定，共用白夜战斗机制与完整原动作。原 Unity 的动态骨求解器未移植，不额外编造衣物或表情动作。角色现在按原始中立姿态的真实蒙皮尺寸统一缩放，修正了白夜根骨 1.1 倍缩放被旧静态外框漏算、导致对话中额外偏高的问题；不修改原关节或对话镜头。

白夜全部五套外观现已接入：原装、红叶知秋、春风之旅、玄衣素裳、黑执事。新增外观保留各自原骨架、衣发骨、蒙皮和 23 段原动作；玄衣素裳的镂空衣料按原材质阈值裁切。月轮原装和血月魔影均补全原独立拳套装备，常态与月食均可见；血月保留原装备骨层级和动作曲线。后续章节也保留历次移植的技术记录，当前可玩内容以本页外观表及 `scripts/fighter_roster.gd` 为准。

太虚仙忆等待界面的衣摆黑片来自双面布片与描边争抢深度。已按原材质恢复 `_MaxOutlineZOffset × _Scale × (COLOR.b − 0.5)` 的视线方向偏移，覆盖 Body 全部 3 层材质；未更改网格、权重、待机动作或衣物运动。原图问题的 32 帧同姿态对照见 `build/screenshots/skirt-outline`。

识之律者使用本机客户端的真实 C6_FL 模型、贴图与材质参数，包含 193 根原骨骼。原导出器遗漏的 Humanoid 运动现通过源肌肉曲线与原 Avatar 轴向、旋转和关节限制重建，形成 24 段动作库，并合并原武器、服装与副骨轨道；身体运动不再依赖炽翎。它不是 Unity 逐位烘焙，源手足定位误差与骨长验证记录在 `../hi3-fuhua-extract/exports/sentience-native`。NewFace 使用原完整面部 UV 与原表情形态。

敌人按剑、枪、链切换打法：剑连续压制，枪拉开距离突刺，链横扫；首领半血进入强化并释放入梦重招。金色预警可防反，红色预警不能格挡，可闪避或用技能打断；防反会打断敌方后续连招。原动作的取段、预警、伤害和碰撞距离按横版重新设计；原链段在保留握柄、身体与摆动方向的基础上限制最大伸展约 3.2 米，适配当前场地。原特效纹理使用适合网页的几何与播放时序，不宣称完整复刻原 Unity 粒子系统。

主页可选择明镜、流转、破阵三条契约，分别强化防反追击、闪避后的技能回转、架势击破。首次通关前单选；完成一次六关试炼后解锁多选与全部勾选，至少保留一条。每多选一条，敌人伤害增加 10%、追击间隔缩短，同时各契约的玩家效果均生效。多约考验需在同一关完成全部目标，额外补给仍只发一次；重试保持原阵容和压力，已选项和解锁存入本地记录。每轮的幻身类型与左右阵型变化；12 种强化中每轮已选项不会重复。完成每关考验额外获得补给与分数，通关保存称号；重试当前关保留同一阵型与构筑。

剧情跟随每次强化选择：12 张强化各有专属短场，4 对组合按取得顺序对应 8 段不同对白，6 种转向也会切换完整场景。五次选择累计形成偏进攻、偏守势、偏流转或兼修的招路，决战以及胜负对白据此回收。同一种转向的谈话在一局中不重复；曾被组合剧情覆盖的转向不算已经谈过。每次选择只播放一段对话，最后一次才接决战邀约，不再每关追加统一的催促或点评。使用当前符华外观和识律的实时 3D 模型，ENTER / 空格或点击推进，ESC 可跳过；跳过不撤销已选择的强化，也不重复发奖。重试保留招路，另开一轮重新记录。所有对白为原创同人内容，未使用原游戏剧情台词或语音。

当前对白采用用户提供的 `docs/story/archive/符华与小识_自然对白润色版.txt`，可编辑对照稿另存于 `docs/story/archive/对白修改稿.txt`；润色版未含 A01、A02，因此使用此前用户截图的9句补齐，共49段188句，逐字接入，不再润色。版本为 `user-dialogue-1`。剧情围绕演武署名、请人观战、庭院与记忆的差异、六场结束后的出游展开，强化选择负责引出话题。完整场景放在 `scripts/sentience_dialogue.gd`，序章、终局和选择解析在 `scripts/sentience_story.gd`；来源与修改记录见 `docs/dialogue-reference-notes.txt`。普通对话采用固定双人构图，显示全文或换发言人时不移动镜头，原版待机动作不从头播放。

## 试玩

双击本目录的 **启动网页试玩.cmd**，或在本地服务运行时打开 <http://127.0.0.1:4187/>。点击“开始试炼”挑战六场连续战斗，也可选择“与识之律者切磋”。网页需要支持 WebGL 2 的浏览器；本机已用 Edge 验证。

主页使用原作女武神头像选择装甲，五套装甲按三张加两张分为两行，全部直接显示，没有横向滚动条。白夜五套外观也分为两行。选中后显示 E / Q 摘要、完整招式说明和外观。拖动右侧角色可 360° 旋转，双击恢复正面；切换装甲、回到主页会复位，只旋转模型整体，不修改原骨骼动作。

在主页先选择装甲与外观，再进入战斗。云墨原装和太虚仙忆共用招式与数值；炽翎使用独立的拳腿招式。每套流派的外观选择会分别记住，关闭后再次打开可恢复；暂停、战斗与结算期间不能换人，需先返回主页。

主页“招式说明”按当前装甲介绍 J / K / E / Q、格挡、闪避与防反追击，外观共用同一套招式。强化卡统一底色，只有主动悬停或键盘聚焦时才高亮。单挑与 Boss 使用顶部敌方血条，普通群战使用头顶血条；同一个敌人不再显示两份生命值。

最后一敌倒下会播放 1.35 秒 K.O. 收尾，包含短暂定格、慢放和镜头冲击，随后进入强化或结算。多段必杀提前击杀时，在原必杀的收尾一击显示 K.O.；普通群战中途击倒只弹出短暂“击破”计数，继续正常连招。K.O. 可用 Esc 暂停，失焦冻结，演出期间不会提前选择强化。

画面中的按钮也可点击或触控。自由对练初始 SP 充满，试炼初始为 60 SP。试炼不能关闭敌人 AI；自由对练可切换木人。窗口失去焦点时自动暂停。

按住 L 会沉身进入拳架，松开后收势；普通受挡有身体承力，极限防御会转肩拨开。防御使用绝区零莱特轻、重招架动作重定向到符华骨架，保留腰腿与手指动作，并按横版节奏截取；弹反后按 J / K 可立即接管动作，不必等整段收势。攻击的收招阶段可以转格挡或闪避，出招前摇仍需承担风险。J 三连和 K 的玩家前摇已缩短，敌人的重击预警保持原长度。轻击、重击、格挡与弹反分别使用不同的命中停顿和声音；命中时人物与水墨同时定格，随后平滑击退，空挥只有风声。

炽翎的拳式出招较快，腿式距离更远；换式带有衔接攻击。极限防御后及时按 J 可使用当前拳 / 腿式的追击动作。这些按键、伤害、冷却、接触点和横版连招规则由本项目设计，并非原游戏整套装甲机制的复刻。

首次开始游戏后播放本机崩坏3客户端的神社战斗 BGM，43.8 秒整段循环。第五关切换识律战曲《Nrbl》，第六关切换《Hard Bone》，战后剧情和结算延续当前曲目；返回首页或自由对练恢复神社曲。音乐开关会保存；暂停或窗口失焦会暂停音乐并从原位置续播，普通命中停顿不打断音乐，大招期间略微降低背景音量。音乐开关只影响 BGM，保留打击音。

角色语音使用本机客户端 `chinese(prc)` 音频包中的原中配：云墨与识律有独立战斗语音，炽翎和白夜使用符华共享战斗语音，并按原动作事件或当前动作的用途匹配短喝。玩家出招、技能、大招、闪避与受击，以及识律剑、枪、链的进攻有对应触发。识律登场使用原中配“我将，扭转万象！”，跳过演出会结束这句；战斗入梦必杀独立触发原必杀语音。云墨保留两条装甲专属大招句，炽翎和白夜当前为核对过的原战斗短喝，不标成未定位的装甲专属长句。普通语音有触发间隔和避免连续同音的选择；玩家与敌方最多各说一句，群敌共用一条声音，Boss 优先。大招句尾可继续到战后界面；切入剧情、返回主页或换人时停止旧声。语音播放时 BGM 略微降低，V 与 M 分别保存设置，显式暂停 / 失焦会暂停语音，打击停顿和慢放不改变音高。

已撤下对白按情绪自动匹配短语气音的方式，避免用同一个“嗯”覆盖大量台词。188 句已确认文案保持不变。角色战斗语音独立保留，资源的原包、银行、事件、媒体编号与语言证明记录在 `assets/audio/voice/manifest.json`。

角色站位以骨盆为中心，避免长发和衣摆造成的模型偏移让双方身体重叠。镜头冲击只在实际接触时触发，暂停会冻结角色、特效与镜头。

普通战斗镜头较近、俯视较小；多人或相距较远时自动拉开，保留两侧敌人。云墨 J 第三段、K、E 重新分配原动作的蓄势、快速释放与收势时间，伤害判定和接触时刻不变；炽翎采用自身原动作的独立选段。角色采用随朝向保持稳定的前侧主光，脸部和眼嘴保留原贴图细节。

本轮角色材质从本机客户端的编译 Shader 恢复普通光照分支：三套外观分别绑定自身身体、头发、脸部的原参数。修正了衣身与描边的分区偏移，恢复头发高光与太虚仙忆衣料的软高光；FaceMap 使用真正含信息的透明通道，另叠加对应发型的 FaceLightMap，而非把全白 RGB 当成无效遮罩。原客户端与当前网页渲染均使用 Gamma 值域，不额外重复颜色转换。原深紫色二级衣影的人工叠加已移除，敌人也不再整身覆盖为单一青色。

普通拳脚的墨刷缩短，避免连击叠成一团；重击与寸劲命中使用原 `SFX_Fluid_304` 黑白方向喷墨。格挡与弹反在手部显示青白弧光，弹反有独立爆裂形状。重击、弹反与架势击破出现短促的外围压暗和放射线，中心为双方身体留白，并在命中停顿时保持同一画面；普通轻拳、空挥和普通格挡不触发这层强调。受击亮边替代原先的整身金色染色。

## 三重试炼

晨岚台、竹影庭、赤霄坛各两场，共六场、十一名对手。多人战中敌人轮流主攻，注意两侧预警。最终的赤霄守影半血后进入第二阶段；红光重击需要及时闪避，寸劲与架势击破可以制造反击机会。

前五场过关后恢复 6 HP、20 SP，并从三项强化中选一项。强化涵盖攻击、SP 获取、生命上限、架势伤害、寸劲冷却与弹反回血，效果会跨战斗保留。失败可以重试当前战并保留强化；重试有最低生命/能量补给，但会影响评分。R 重新开始整轮试炼。

群敌可在前一位收招时开始下一次预警，接触窗口仍错开。精英与小识受连续压制后会在硬直结束时使用原闪避或防御接武器反击；防反和架势击破仍保留稳定追击窗口。Boss 反击连段可用 K、E 或极限防御中断，普通连打难以一直压住。后三关提高失误代价，敌人数与生命值保持原预算；达成契约仍有额外补给。

通关显示击败数、连击、极限防御、承伤、耗时与评级，最高分保存在当前浏览器的本地数据中。

## 胜利展示与角色扩展

自由对练获胜和六战通关后播放 4.4 秒胜利展示：云墨使用原生 `Victory` 的 3.8 秒背身收势、转身回望，再衔接 `VictoryIdle`；炽翎使用自身 `Victory` 与 `Victory_idle`。太虚仙忆保留云墨结算动作。镜头由本项目编排，最后角色留在左侧、成绩放在右侧。Enter 跳过，Esc 暂停，失焦自动暂停；成绩页可重播、再次开战、切换模式或返回主页。演出和重播拥有独立时间线，不重新计分。中途强化页和失败不触发胜利演出。

胜利库保留身体和服饰动作。三套外观已接入原眼睛和嘴部图集：待机眨眼、战斗目光、发力和受击口型、大招闭眼蓄势，以及结算微笑。表情切换时序由本项目编排，暂停和命中停顿会同步冻结。原版另行触发的 `IN_Fuka_Winning` 目前只定位到触发事件，独立表情曲线、胜利粒子和语音尚未移植，不将当前演出描述为原客户端结算的完整复现。

角色目录 `scripts/fighter_roster.gd` 按“角色 → 战斗流派 → 外观”组织。角色表示人物身份；招式或战斗机制不同的装甲属于独立流派；共用招式的皮肤归入该流派的外观。当前正式可玩的五套流派、十二套外观见上表。Actor 和 HUD 从目录读取模型、动作与人物名称，切换流派同步切换战斗规则。炽翎的内部流派 ID 沿用 `fenghuang`，实际模型为 `C4_JW`。

太虚仙忆使用真实 `C5_04_02` 外观模型，身体与头发几何均不同于原装。其主体骨架复用云墨动作，另为长发、衣摆和系带的 14 条骨链重建有限角度的跟随与回摆。原 Prefab 中 6 个 DynamicBone 的挂点已核实，发根和后裙腰根保持固定；不改变身体动作或骨长。动态跟随、重力补偿和表情时序为本项目实现，尚未复现原客户端的布料碰撞求解。

太虚仙忆前衣摆仍穿出蓝色裤腿的另一处问题来自衣物碰撞范围过小：旧腿部半径未覆盖原裤腿网格。现在仅在角色加载时按原绑定网格测量覆盖半径，沿用附件碰撞约束分开裤腿和衣片，原身体骨、蒙皮、权重、UV 和动画均不改。对话播放原片后也执行衣物接触校正；原身体与表情仍逐骨使用原动作，衣物骨保留原局部长度。菜单和对话各六个采样时点的前裙/裤腿三角相交由 82–106 对降为 0，另检查四个观察角度和原胜利动画。

太虚仙忆衣身已接入 `assets/azure-skin/native-body-uv2.res`：按原 8,883 个源顶点和三角拓扑恢复第二组 UV，保留 UV2 接缝，解决直接匹配导入顶点时出现的 106 处候选歧义。分材质保存后为 8,906 个顶点、10,176 个三角形；位置、第一组 UV、骨索引和骨权重保持不变，沿用已有蒙皮与骨架绑定。此修复让原材质的背面 UV2 分支有准确坐标可用，不改变角色招式或服饰动态规则。

炽翎当前未装配原游戏的外置拳套，手部采用本体颜色图恢复可见；这是无拳套的展示适配。其面部、头发与衣饰使用对应原模型的贴图和材质分区。

本机其他符华装甲已有不同程度的动作导出或模型索引，详见 `../hi3-fuhua-extract/exports/符华可选角色与胜利动作审计.txt`；模型索引不等于已可使用的模型。

开发限制：本轮尝试的 `C7_GM` 主体使用 Humanoid muscle 曲线，现有转换没有得到可用的身体运动，且本机 Unity 尚未激活可用授权。因此该装甲未登记、未放入网页；本轮新增可玩流派来自动作完整的 `C4_JW` 炽翎。

## 编辑与导出

普通 `git clone` 即可取得源码和当前运行资源，不需要 Git LFS。仓库根目录就是 Godot 项目，使用 **Godot 4.7.2** 打开 `project.godot`。编辑器与同版本官方导出模板需自行安装；Node.js 用于本地网页服务，需能在命令行调用 `node`。运行当前游戏不需要 Unity、原游戏客户端或提取工具。

首次克隆后先导出，再启动网页：

```powershell
# 将路径替换成自己的 Godot 4.7.2 可执行文件。
.\build-web.ps1 -GodotPath 'C:\Tools\Godot\Godot_v4.7.2-stable_win64_console.exe'
.\start-web.ps1
```

`build-web.ps1` 按 `-GodotPath`、环境变量 `GODOT_BIN`、PATH 中的 `godot` / `godot4` 查找编辑器；也兼容本机原来的 `../tools/godot/Godot_v4.7.2-stable_win64_console.exe`。编辑器路径配置好后，可直接双击 **重新导出网页.cmd** 与 **启动网页试玩.cmd**。PowerShell 如阻止脚本运行，可以使用这两个 `.cmd` 入口。

导出默认使用安装在 Godot 中的同版本官方模板，采用无线程 Web 与 Compatibility 渲染器。若使用单独解压的模板目录，指定 `-WebTemplatesPath` 或 `GODOT_WEB_TEMPLATES`，该目录应含 `web_nothreads_debug.zip` 和 `web_nothreads_release.zip`；编辑器旁的 `web-templates` 目录也会自动识别。本机旧便携目录因此仍可直接使用。脚本只在导出期间临时填入自定义模板路径，并在结束或失败时恢复原预设文件。`-CheckOnly` 仅显示解析后的编辑器和模板位置，不导入或导出资源。

`build/web` 是网页成品目录，需要第一次自行生成；通过 HTTP 服务访问，不能直接双击 `index.html` 运行。也可在任意支持 Node.js 的终端运行 `node server.mjs`，再打开 <http://127.0.0.1:4187/>。当前服务仅监听本机，没有发布到外网。

仓库包含 `assets`、`scripts`、`shaders`、`tests`、`docs` 和启动/导出文件。`.godot` 导入缓存、`build` 成品与测试输出、旧版 `fuhua-demo`、原始客户端提取备份、编辑器和演示视频保留在本机，不作为此仓库内容。下文部分源资产比对测试引用了这些本机提取目录；这类专项审计需要对应原始备份，普通游戏运行与网页导出不依赖它们。浏览器测试脚本中的开发机浏览器工具路径也需按测试环境配置。

防反接续：成功拨挡后的停帧和 75 毫秒收势会保留当前姿势，J/K/E/Q/闪避输入只缓存最后一条合法指令，在收势结束后执行。云墨与炽翎均可在成功后的 1 秒内主动追击，复用原动作接触姿势并缩短重复起手；如果被拨挡的同一对手尚在该次硬直中，会补足到这次追击接触，已经恢复或另受攻击的敌人不会被重新定住。追击及随后命中接续的连段优先原对手，避免其被推出后突然转身打另一侧；目标死亡或离开近距立即恢复普通选敌。炽翎原反击命中或受挡后，J 可直接接第二段，K 可接重击；空挥仍须完成收招。暂停清空待执行指令，新受击、闪避、必杀与重开清理旧追击资格，不自动攻击或追加伤害。

`tests/actor_presentation_suite.gd` 还检查莱特招架的身体骨长、支持脚贴地、进入/保持/收势、重复受挡、J/K 接管及衣发骨停帧稳定性。`tests/browser/defensive-retarget-browser.cjs` 用真实玩家操作验证左右朝向的招架、弹反和反击接续。`tests/music_suite.gd` 检查单播放器状态；`tests/browser/music-browser.cjs` 直接观察网页音频输出，验证启播、静音、暂停续播、大招压低音量及原曲自然循环，避免只凭 UI 状态判断声音正常。

`tests/fighter_roster_suite.gd` 检查全部已登记外观的真实模型、主身体运动、动作选段、眼嘴 UV 与多材质绑定。`tests/roster_selection_suite.gd` 从真实主流程检查模型替换与旧节点释放、流派规则与冷却同步、逐流派皮肤记忆、保存恢复、非法配置回退及战斗中拒绝换人；测试隔离 `user://`，不会改变玩家的实际偏好。两套测试可加 `-- --require-fenghuang`，明确要求炽翎完成登记与适配。

`tests/phoenix_defense_suite.gd` 检查炽翎独立防反库的双朝向、骨长、接地、暂停冻结、重复受挡与 J/K 中断。`tests/victory_presentation_suite.gd` 检查真实结算触发、动作衔接、暂停、跳过、重播、计分不变及重开清理。`tests/browser/victory-browser.cjs` 通过正常玩家输入验证网页胜利演出和结算按钮，截图保存在 `build/screenshots/victory`。结构与流程测试不代表所有动画逐帧视觉验收。

`tests/ultimate_camera_suite.gd` 检查分镜镜像、窄屏取景和确定性；`tests/browser/ultimate-camera-browser.cjs` 实测分镜、暂停、归位、左朝向及场边致命必杀。运镜由本项目编排，关键姿势构图参考 Arc System Works 的 [Guilty Gear Xrd 开发者讲义](https://www.ggxrd.com/Motomura_Junya_GuiltyGearXrd.pdf)，并非复刻某个角色的超必杀动画。

`tests/visual_presentation_suite.gd` 验证近景、场边、多人及窄屏构图，以及命中强调的触发、冻结和清理；角色测试还检查强攻击的非线性采样、精确打点和恢复。关键姿势、独立角色光照和分区轮廓的处理参考同份讲义第 20、24、27–29 页；本项目的具体时间、shader 参数和效果编排为适配云墨动作自行设计，并非罪恶装备原参数。

`tests/browser/visual-iteration-browser.cjs` 用普通输入检查连击、真实防御、强命中强调、空挥、暂停、必杀归位和第二关双侧敌人，并保存大窗口与 960×540 实机截图到 `build/screenshots/visual-iteration`。

`tests/probes/scene_art_probe.gd` 用于三地域的固定镜位展示，以及必杀时场景整体隐藏、结束后恢复的检查；加 `--capture` 可保存大窗口和小窗口原生截图。`tests/browser/scene-art-browser.cjs` 通过正常闯关操作到达三个地域，检查实际 HUD 下的取景、960×540 小窗口和必杀前后的场景恢复。两者仅用于开发验收，不提供试玩中的跳关接口。

`tests/native_stage_material_suite.gd` 从真实 Arena 依次加载三个地域，逐材质检查原纹理、烘焙强度、基础 Matcap 开关与遮罩、法线 ST、有效切线，以及切换地域时材质和场景节点的释放；也检查必杀隐藏与恢复、网页导出所需动态材质表。结果写入 `build/reports/native-stage-material-suite.json`。这些无渲染检查与 `build/screenshots/scene-art-native` 的实机截图分开记录，不以材质绑定通过代替画面验收。

`tests/browser/roster-browser.cjs` 使用实际菜单和普通战斗输入验证两流派、云墨换装、刷新后各流派的外观记忆、禁止战中换装、炽翎换式与必杀暂停、实战获胜和原生结算。新网页实测 11 项通过，浏览器错误为零；1280×800 与 960×540 截图位于 `build/screenshots/roster-web`。炽翎原必杀的大幅根骨腾空已压缩到横版镜头内，起手镜头为发冠与电影黑边留出余量；伤害时点和镜头时间采用本项目编排。
